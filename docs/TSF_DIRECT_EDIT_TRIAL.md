# TSF直接編集の実現性試験

ブランチ：`codex/tsf-direct-edit-feasibility`。
実現性試験を経て通常起動へ統合した。通常の手動UIA置換・監視専用DLLとは分離している。
Obsidianのコードやプラグインを変更する修正ではない。診断時だけ既存の読み取り用内部監視を利用する。

## 通常起動への統合

設定は`auto_replace_on_ime_commit = true`と`ime_commit_backend = "tsf"`。
このワークスペースのconfig.tomlにも反映済みで、起動は次でよい。

```powershell
python -m kana_rewriter --config config.toml
```

手動ショートカットは従来のWin32/UIA処理、自動確定はTSF直接編集に分かれる。
TSF方式の失敗・未対応入力欄でUIA自動置換へ切り替えることはない。
設定省略時は互換性のためuia。CLIの`--ime-commit-backend tsf`でも明示できる。
監視用DLLと編集用DLLは配布ZIPにも両方含める。

`diagnose_obsidian.py --tsf-edit`も現在は通常起動へルーティングし、
従来の`--fixed-source/--fixed-result`は通常CLIのbenchmarkオプションに変換する。
試作モジュールは比較用に残すが、通常経路はそれをimportして編集しない。

## 実装した処理

1. TSFのIME確定通知で、確定範囲のITfRangeを保持し、通知にcommit_id/revisionを付ける。
2. UIAは対象本文とAI用文脈の読み取りにだけ使う。Select・SendInput・IME切り替えは呼ばない。
3. 対象スレッドの制御ウィンドウへ要求を送り、TSFにread/write編集セッションを要求する。
4. 保持範囲・文脈・revision・フォーカス・未確定範囲なし・範囲本文を確認し、SetTextを一度だけ実行する。
5. 同じTSFセッションで範囲本文を読み戻し、TSFのカーソルを末尾へ設定・確認する。
6. 完了イベントで要求元を起こす。固定sleepによる編集待ちや別方式へのフォールバックはない。

新規入力・文脈変更・本文不一致は書き込み前に中止する。一度処理した確定範囲は再利用しない。
書き込みAPI呼び出し後の失敗は「編集済みまたは結果不明」と報告する。
タイムアウト時、未実行・書き込み前の要求をキャンセルし、書き込み開始済みなら結果不明として扱う。
タイムアウト後の要求メールボックスは再利用しない。結果不明の場合も実験全体を停止し、再起動を要求する。
最大待ち時間は失応答時の上限であり、通常の成功処理でその時間まで待つものではない。

ITfThreadMgr::Activate/Deactivateを対応させて編集クライアントIDを取得する。
IME/TIPの登録・既定IMEの変更はしない。

## ビルド

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/build_tsf_edit_probe.ps1
```

生成物は`build/tsf-edit-probe/`。通常の`build/tsf-probe/latest.json`は変更しない。
ロード済みDLLを上書きしないよう、新しいファイル名を毎回発行する。
実験DLLの通知形式は101で、通常版の形式3とは相互に取り違えない。
本試作は既存のllvm-mingw 64ビットコンパイラーを使う。

## 利用者によるObsidian試験

通常版のかな変換プログラムを終了してから実行する。
最初はAIを使わず、完全一致した対象だけを固定文字列に置換し、編集経路そのものを確認する。

```powershell
python scripts/diagnose_obsidian.py --tsf-edit --fixed-source "へんかんてすと" --fixed-result "変換テスト"
```

Obsidianを再起動・再読み込みせず、同じ箇条書きの1行内で「へんかんてすと」の入力とEnter確定を繰り返す。
結果が出たら端末でCtrl+Cを押して終了する。半角全角キー等の手動変換はこの専用試作では登録しない。
終了時に内部監視を解除・保存する。`logs/obsidian-日時-*`のDOM・編集・sessionログを解析する。
ログには入力本文が含まれる。

AIを含む試験は固定文字列指定を外して実行する。

```powershell
python scripts/diagnose_obsidian.py --tsf-edit
```

`--tsf-edit`を外せば従来のUIA診断起動になる。実験版がUIA失敗後に起動する構成ではない。

## 合成TSFアプリでの検証

```powershell
python -m unittest tests.test_tsf_edit -v
```

実際の別プロセスのTSFアプリ、COM編集セッション、範囲SetTextを使い、文字入力はSendInputに置き換えていない。
対象アプリは合成のITextStoreACPで、Obsidianではない。

- 直接置換後のTSF内本文とカーソル、および実ウィンドウの本文を確認する。
- 本文不一致・次の未確定入力・確定範囲の再送を中止する。
- 対象スレッドをテスト内だけ停止し、要求タイムアウト後に遅れて書き込まないことを確認する。
- 書き込みAPIの中で停止するケースは結果不明と判定し、再送・後続編集をせず実験が終了することを確認する。
- 非同期にTSFロックが許可される場合も、保持範囲が有効なまま編集セッションを実行できることを確認する。
- 1,000回の反復で長さの異なる文字列・絵文字・削除を検証する。
- UIA置換・キー送信が呼ばれず、失敗時に再送しないことを確認する。

最初の1,000回は全件成功し、要求からTSF内の確認まで中央値15.657ms、最大17.043msだった。
これは合成アプリのメッセージループやスケジューリングを含む数値であり、
Obsidianや全体の変換速度を表すベンチマークではない。

## 実現性の判定範囲

合成アプリでは、IMEを登録せずに別クライアントから保持した確定範囲を編集できることまで確認できた。
下記の利用者による実操作により、Obsidianでも固定文字列の繰り返し置換が成立した。
下記の追加実操作でAI込みの経路も確認した。Undo/Redoや他の入力欄までの適用範囲は引き続き検証対象。
以下は統合前の実現性検証の記録。現在の通常起動への統合内容は冒頭を参照。

## Obsidianでの実操作結果（2026-10-22）

セッション `logs/obsidian-20261022-074936-180823-*` を解析した。
実操作は利用者が行い、同じ箇条書きの1行内での入力と確定を繰り返している。

- sessionのmodeはtsf_edit、valid=true。内部監視の欠落・保存エラーは0。
- TSF編集予定11件、直接編集成功11件。全件hr=0、state=3。
- CodeMirror内の行が「変換テスト」1個から11個へ順次増え、各置換完了時の内部カーソルも末尾にある。
- 最終DOMも「変換テスト」11個で、DOMカーソルは末尾55:55。CodeMirrorも空選択・文書末尾。
- UIA選択要求と通常のSendInput送信のログは0件。UIA経由への切り替えで成功したものではない。
- TSF編集要求から範囲本文・カーソル確認まで中央値0.482ms、最小0.264ms、最大2.409ms。

上記時間はTSF適用部分のみで、IME確定の通知・UIA文脈取得・AI推論・DOM反映までの全体時間ではない。
DOMログはperformance由来、Pythonログはシステム壁時計由来であり、長時間稼働後の絶対時刻には差がある。
両者の数ms単位の絶対時刻差を遅延算出に使わず、候補文字列と順序・完了後の本文で対応を確認した。

抽出した集計は同接頭辞の`-analysis.json`へ保存した。
この条件でTSF直接編集の実現性は確認できた。すべての入力欄・文字列での安定性やUndoの動作までを保証する結果ではない。

次段階は固定文字列指定を外した `python scripts/diagnose_obsidian.py --tsf-edit` によるAI込みの試行と、
置換後のUndo/Redo・入力継続・入力先変更時の中止の確認とする。

### AI込みの追加実操作（08:09–08:10）

セッション `logs/obsidian-20261022-080922-520751-*` を解析した。
GGUFモデルを読み込んでおり、固定結果指定ではない。

- 「きょうもいいてんき」→「今日もいい天気」を3回、「じっそうかくにん」→「実装確認」を1回。
- 直接編集は4件すべて成功。中止・エラー0件。別に、変換不要と判定して書き込まなかった結果が1件。
- CodeMirrorのトランザクション後の本文に、両方の変換結果が反映されている。
- sessionはvalid=true。内部監視は終了まで継続し、欠落・保存エラーなし。
- UIA選択要求・通常のSendInput送信は0件。
- TSF適用部分の中央値0.777ms、最大3.398ms。AI推論を含む全体時間ではない。

利用者からも問題なく動作するとの報告があった。この実操作範囲ではAI込みでの実現性も確認できた。
Undo/Redoの操作と結果を特定できる記録は今回のログから確認できないため、Undo/Redoまで検証済みとは記載しない。
全入力欄への互換性・長期安定性は引き続き検証対象とする。通常起動への統合は冒頭の設定で選択できる。
集計は同接頭辞の`-analysis.json`へ保存した。
