変換プレビュー UI 候補

現在のWin32プレビュー（単色矩形・16px Yu Gothic UI・12pxパディング・角丸なし）を基準に、5案を等倍モックで並べています。 実際の候補はカーソル右下の8px下に表示され、画面下端では上へ反転します。ブラウザ描画のため、字詰め・アンチエイリアスは実機のGDI/ClearTypeと少し異なります。 色は preview_window.py のブラシ値（背景 #182333 / 文字 #F4F7FB）を再現しています。

採用：C（読み＋結果の2行）。読みを上段、変換結果を下段に置き、変化点を確認しやすくします。読みと結果が同じときは1行で表示します。 このページは比較用の静的モックです。A・B・D・Eは未実装です。

A

角丸ダーク＋影

候補

色と文字サイズは現状のまま、容器だけを整える案。角丸10px・1px境界線・弱い影で、明るい背景でも暗い背景でも輪郭が保てます。情報量を増やさないので「入力の邪魔をしない」という現行の性格を維持します。

変更点
角丸、1px境界線、ドロップシャドウ、パディングを 12px → 11px 14px。
実装
Win11は DwmSetWindowAttribute の角丸指定でDWMがアンチエイリアス付きで描画。Win10は SetWindowRgn になり角がギザつく。影は CS_DROPSHADOW で概ね足りる。影の分だけ測定サイズに余白を足す必要あり。低
B

ライトの紙面カード

明るい背景に馴染む、紙のような淡色カード。境界線と影で本文から浮かせます。日本語の本文は白背景が多く、変換結果を「読む」ことに集中できる配色です。ダークテーマのアプリ上ではやや浮きますが、影があるため視認性は確保できます。

変更点
背景 #FCFBF7、文字 #1E2328、境界線 #DCD8CF、角丸8px、影。
実装
ブラシと文字色の変更＋境界線でほぼ完結。不透明面なのでClearTypeもそのまま使える。低
注意
アプリごとのテーマ（VS Codeのダーク等）はWin32から確実に取れないため、自動追従はしない前提。システムテーマに追従させるとアプリとの不一致が起きます。
C

読み＋結果の2行

採用

上段に未確定の読み、下段に変換結果を置く案。「何がどう変わるか」がその場で分かり、誤変換にも気づきやすくなります。ただし高さが約1.4倍になり、視線の移動も増えるため、速い入力にはやや重い可能性があります。

変更点
読み用の小フォント（11.5px / グレー）を追加し、左に3pxのアクセントバー。PreviewTarget.target をUIまで渡す配線が追加で必要。
実装
フォント2本、DrawTextW 2回、高さ計算の変更。中
注意
読みが長いと幅480pxの上限に当たる。読み側は DT_END_ELLIPSIS で省略するか、2行目だけ基準に測る。
D

アクセントピル＋ショートカット

視認性◎

青のピルに白文字、右端に変換キーのキーキャップ。どんな背景でも埋もれず、「確定はショートカット」という現在の操作モデルも伝えられます。一方で色が強いため、長文を書いている間は視線を引きすぎる可能性があります。

変更点
背景をアクセント色に、角丸をピル形状に。キーキャップは半透明の白で描く。
実装
丸角は RoundRect（アンチエイリアスなし）か、Win11の角丸指定は半径固定のためピル形状には使えない。キーキャップ用に角丸矩形とブラシがもう1組必要。中
注意
hotkey_line は設定で変わるため、キー表示は設定値から引く。表示と実際の変換範囲（区切りまで）が一致しない場合がある点は現行と同じ。
E

差分を色分け

意味づけ

Aの容器に、読みから変化した部分だけ色を付ける案。どこが漢字になったのか一目で分かり、誤変換の確認が速くなります。色数が増えるため、ダーク背景ではコントラストの調整が必要です。

変更点
読みと結果の文字単位差分を取り、変化した連続区間をアクセント色（#A8D8FF）で描く。
実装
差分計算＋区間ごとの DrawTextW。文字幅の逐次測定が必要で、折り返し・幅上限の扱いも複雑になる。高
注意
送り仮名だけ変わる場合（例: おくる → 送る）は、色分けが細切れになって読みにくいことがある。

設計上の制約（実装前に確認したい点）

  • 半透明はClearTypeと相性が悪い。現行は不透明な面に直接描いてClearTypeを効かせています。背景を透かすにはレイヤードウィンドウ＋32bit DIBが必要で、サブピクセル描画が濁ります。候補はすべて不透明前提です。
  • 角丸はWin11とWin10で品質差が出ます。Win11のDWM角丸は滑らか、Win10の SetWindowRgn はギザつきます。両対応なら「角丸なし＋境界線＋影」も選択肢です。
  • アプリのテーマは取得できません。Windowsのシステムテーマとアプリのテーマは別物です。ライト／ダークの自動切替はせず、どちらでも成立する1案に固定するのが安全です。
  • 影の余白ぶん位置が変わる。place_preview の gap=8 / clearance=24 に影のマージンを足さないと、影が切れるかカーソルに近づきすぎます。
  • 幅の上限は現行480px。C・Dはキーキャップや読みのぶん実効幅が減るため、長い候補での省略規則を先に決める必要があります。
