# 入力監視・変換・表示の責務

## 実行経路

1. `notifications.NotificationPump` がTSF DLLの通知を専用スレッドで回収する。UIAの同期呼び出しやログ出力を実行しない。
2. `auto_ime.FocusReader` が現在の入力欄の編集可否とウィンドウを検証する。UIA編集ではTextPattern提供要素のRuntimeIdも照合する。TSF直接編集ではUIAの要素自体が確定時に再生成されるため、RuntimeIdを文書識別に使わず、TSFのcontext通知・文脈世代と保持した確定範囲を使う。
3. `commit_state.CommitState` が受付開始時刻、入力リビジョン、保留確定、推論中の状態を管理する。
4. 通常起動のメッセージループが取得・推論・適用を実行する。TSF編集は `tsf_edit.TsfCommitEditor` が確定範囲と原文・文脈を検証する。手動変換には設定済みの編集方式を使う。
5. `preview_state` はIMEセッションと候補の順序だけを管理し、`preview` はTSF取得・推論IPC・子プロセス終了を管理する。`preview_window` は非アクティブな最前面表示、読みと結果の2行描画、対象画面の作業領域内への配置を担当する。

## 安全性と寿命

- 通知回収は単一の読み手だけが行う。Pythonの受信箱も4096件で制限し、欠落時はその履歴を利用しない。
- 自動変換で通知が欠落した場合、保留・推論中の対象を無効化し、解除確認後に同じTSF方式を再接続する。解除できない監視や結果不明の書き込みは続行しない。別方式へのフォールバックや書き込みの再送は行わない。
- 通知回収スレッドの停止確認後にDLLを解除する。取得中の共有メモリーを解放しない。
- フォーカスが実際に別文書へ移れば以前の推論結果を適用しない。HWNDだけの一致では入力欄が同じとは判定しない。
- TSF直接編集ではRuntimeIdのみの変化で通知を捨てない。成功したcontext通知の世代に一致し、確定ID・ネイティブリビジョンを持つ通知だけを受け付ける。同じHWND内でもcontext変更で以前の結果を無効化し、適用直前にはネイティブ側で原文・選択・文脈を再検証する。ウィンドウの実変更時は監視を解除して新しいcontextを取得する。
- プレビュー取得失敗・通知欠落は親へ報告し表示を消す。取得が500ms以上更新されない場合も表示を消す。終了時は子へ終了要求を送り、TSF解除を待ってからプロセスを回収する。
- プレビューは同じウィンドウ・スレッド内のRuntimeId変動でTSFを再接続しない。context・確定・取消通知で表示セッションを区切る。IMEが空になった旧合成範囲を新しい範囲へ置き換えた場合、入力中の範囲が残る限りプレビュー全体の終了通知を出さない。空文字や変換対象のない入力では表示を消し、次の有効な入力で新しい候補を要求する。
- パイプの各方向はそれぞれ単一スレッドが送信する。取得スレッドの例外も共有状態を介してUIスレッドから通知する。
- プレビュー中のUIA同期検証はウィンドウ・TSF文脈・合成範囲の切り替わりで行い、同じ合成範囲の各文字更新では繰り返さない。本文・位置は引き続きTSF通知を使用する。診断ログでは入力先検証、推論待機、推論時間を区別する。
- 画面端の配置は対象画面の作業領域とDPIで事前に計算する。DPI確認には非表示の専用ウィンドウを使い、表示中の候補をカーソル位置へ仮移動しない。文字の折り返し幅を作業領域に合わせ、最終位置・サイズが同じフレームでは再移動しない。同じ入力行で上側へ移した候補は、候補が短くなっても下側へ戻さない。非表示化または入力行・画面の変更でこの配置方針をリセットする。
- 未確定範囲内のカタカナを、確定済みカタカナの区切り規則で除外しない。長音符・結合濁点は直前の文字種に従って区切りを判断し、「ぷれびゅー」や「こーひー」を途中で切らない。

## ビルドと検証

`scripts/build_tsf_probe.ps1`、`scripts/build_tsf_edit_probe.ps1`、`scripts/build_preview.ps1` でDLLを作成する。配布には三つとも必要。マニフェストのソースハッシュで古いDLLの混入を拒否する。

```powershell
.venv/Scripts/python.exe -m unittest discover -s tests -v
```

通知回収の順序・欠落・例外、遅いUIA取得、文書切り替え、推論中の入力、実TSF確定範囲、プレビューIPCと実HWNDの表示を回帰試験で確認する。合成編集アプリの試験と実アプリのIME操作は異なるため、Obsidian等の実入力による互換性確認は別途必要。

## 整理方針

通常起動へ統合済みの `tsf_edit_trial` と単発の性能比較スクリプト・古い計測資料を削除した。固定結果での再現は通常起動の `--benchmark-source` と `--benchmark-result` を使う。実編集・通知の回帰試験と、利用・配布・モデルライセンスの資料は維持する。
